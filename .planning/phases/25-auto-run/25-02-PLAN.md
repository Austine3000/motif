  <action>
Create `.claude/get-motif/scripts/runtime-session.js` as the durable session helper for Phase 25 and integrate it into `runtime-launcher.js`.

The session layer must:
- own one project-scoped session artifact under `.planning/` for the active runtime session
- persist fields such as platform, mode, PID (when applicable), status, URL/path, start time, source command, and cleanup outcome
- provide helpers to read/write/update the session atomically
- detect stale session records by checking whether the tracked PID/process still exists
- distinguish daemon sessions from static-preview sessions cleanly

Update `runtime-launcher.js` so daemon runtime management is safe and explicit:
- write a `starting` session before launch
- transition to `ready` only after a valid ready match and preview-open step
- transition to `stopped` or `cleanup-failed` on teardown paths
- handle cleanup for normal exit, `SIGINT`, and `SIGTERM`
- use process-group or platform-appropriate cleanup semantics so child processes launched under `npm run dev` do not survive a parent-only kill on supported platforms
- use a Windows-safe fallback strategy for cleanup without adding dependencies

The implementation should remain conservative:
- do not claim that arbitrary external processes are Motif-owned
- do not require `.planning/design/STATE.md` mutations for runtime session persistence if a dedicated artifact is clearer
- do not let static preview create fake daemon PIDs just to fit the same schema

Finish the operational behavior that makes auto-run predictable on repeat use.

Update the launcher and compose workflow so repeated auto-run follows a deterministic policy:
- if an existing tracked Motif session is alive for the same project, choose a clear reuse-or-restart behavior and communicate it to the user
- if a tracked session is stale, clean the stale record and proceed automatically
- if the target port is held by an untracked external process, warn and do not kill it automatically
- if the framework prints a different working URL/port from the default, trust the printed URL, persist it, and open that URL instead of the guessed default

Surface the runtime state clearly in `compose-screen.md`:
- show tracked PID for daemon runtimes
- show the session artifact path or equivalent debug handle
- explain whether Motif reused, restarted, or skipped launch because of an external conflict
- keep compose success distinct from runtime warnings

Also update `.claude/get-motif/hooks/motif-context-monitor.js` so the persistent status line can show active preview metadata when a runtime session artifact exists:
- preview platform
- tracked PID for daemon runtimes
- resolved URL or static target
- keep the existing next-action hint when no active runtime session exists

If registry data needs small additions to support port policy or preview target hints, keep those additions declarative and platform-specific in `framework-registry.json`.
