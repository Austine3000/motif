  <name>Task 1: Create composer-nextjs.md platform overlay</name>
  <files>.claude/get-motif/references/composer-nextjs.md</files>
  <action>
Create `.claude/get-motif/references/composer-nextjs.md` as the platform overlay document for Next.js App Router projects. This document is injected into the composer subagent's context to override default HTML composition behavior.

The overlay must cover these sections:

**1. File Output Rules**
- Pages: `src/app/{route}/page.tsx` (default export, Server Component by default)
- Layouts: `src/app/{route}/layout.tsx` (only if route needs shared UI wrapper)
- Route-scoped components: `src/app/{route}/_components/{Name}.tsx` (underscore prefix = not a route)
- Shared components: `src/components/{Name}.tsx` (cross-route reuse)
- Page files MUST use `export default function {PageName}Page()` format

**2. Import Rules**
- shadcn components: `import { Button } from "@/components/ui/button"` (lowercase file, PascalCase component)
- Icons: `import { IconName } from "lucide-react"`
- Images: `import Image from "next/image"`
- Fonts: handled by layout.tsx via next/font/google -- do NOT import fonts in page components
- cn utility: `import { cn } from "@/lib/utils"` (for conditional classes)
- When a shadcn component is needed that was not pre-installed, note in SUMMARY.md: "Additional shadcn components needed: {list}. Run: npx shadcn@latest add {component} -y"

**3. Styling Rules (CRITICAL -- this overrides the default inline-style behavior)**
- Use Tailwind utility classes for ALL styling via className prop
- NEVER use inline style={{}} objects
- NEVER use raw CSS custom property references in JSX (no `var(--color-primary-500)`)
- Color utilities: `bg-surface-primary`, `text-text-secondary`, `bg-primary-500`, `text-primary-500`, `border-border-primary`
- Spacing utilities: `p-4`, `m-2`, `gap-6` (Tailwind default scale matches Motif's 4px base)
- Radius utilities: `rounded-sm`, `rounded-md`, `rounded-lg`, `rounded-xl`, `rounded-full`
- Shadow utilities: `shadow-sm`, `shadow-md`, `shadow-lg`
- Font utilities: `font-display`, `font-body`, `font-mono`
- For hover/focus/active: use Tailwind modifiers `hover:bg-primary-600`, `focus:ring-2 focus:ring-ring`, `active:scale-[0.98]`

**4. Token-to-Tailwind Quick Reference Table**
Include a mapping table (from research) showing Motif token -> Tailwind utility for common cases:
| Motif Token | Tailwind Utility | Example |
|-------------|-----------------|---------|
| --color-primary-500 | bg-primary-500, text-primary-500 | `className="bg-primary-500"` |
| --surface-primary | bg-surface-primary | `className="bg-surface-primary"` |
| --surface-elevated | bg-surface-elevated | `className="bg-surface-elevated"` |
| --text-primary | text-text-primary | `className="text-text-primary"` |
| --text-secondary | text-text-secondary | `className="text-text-secondary"` |
| --space-4 (1rem) | p-4, m-4, gap-4 | `className="p-4"` |
| --radius-md | rounded-md | `className="rounded-md"` |
| --shadow-md | shadow-md | `className="shadow-md"` |
| --font-display | font-display | `className="font-display"` |

**5. Component Format Rules**
- "use client" ONLY when component uses: useState, useEffect, useRef, useContext, event handlers (onClick, onChange, onSubmit), or browser APIs (window, document)
- Page components (page.tsx) should be Server Components when possible -- push interactivity down to child components
- Export format: `export default function PageName()` for pages, `export function ComponentName()` for sub-components
- All props typed with TypeScript interfaces

**6. Image Handling**
- Use `<Image>` from "next/image" for all images
- Always provide width and height props (or use fill prop with a sized container)
- Use priority prop for above-the-fold hero images
- For placeholder images during composition: use `placeholder="blur"` with a blurDataURL or a simple colored div

**7. Font Usage**
- Fonts are loaded in the root layout.tsx via next/font/google
- Available as CSS variables on the html element: --font-display, --font-body, --font-mono
- Use via Tailwind: `font-display`, `font-body`, `font-mono`
- Do NOT attempt to load or import fonts in page or component files

**8. shadcn Component Usage**
- Use shadcn primitives where they match the design system spec: Button, Card, CardHeader, CardContent, CardTitle, Input, Badge, etc.
- Apply variant props: `<Button variant="default">`, `<Button variant="secondary">`, `<Button variant="destructive">`, `<Button variant="ghost">`
- Extend with Tailwind classes via className: `<Card className="bg-surface-elevated shadow-md">`
- For components not in shadcn, compose with Tailwind utility classes on semantic HTML

**9. Anti-Slop Additions for Next.js (extend the existing anti-slop checklist)**
- Am I using style={{}}? -> STOP. Use Tailwind className instead.
- Am I writing `var(--color-primary-500)` in JSX? -> STOP. Use `className="bg-primary-500"` or `className="text-primary-500"`.
- Am I using `<img>`? -> STOP. Use `<Image>` from next/image.
- Am I importing a font? -> STOP. Fonts come from layout.tsx via next/font.
- Am I putting "use client" on a page.tsx that only renders markup? -> STOP. Keep it a Server Component.
- Am I using `<a>` for internal links? -> Consider using next/link's `<Link>`.

```markdown
Read STATE.md for the `platform` field (from frontmatter or ## Platform section).

```
