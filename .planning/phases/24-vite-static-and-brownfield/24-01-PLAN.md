Add a post-generation step that:

- invokes `node .claude/get-motif/scripts/scaffold-project.js --platform {platform} --project-root {cwd-or-parent} --project-name {project-name} --design-system-dir .planning/design/system`
- skips execution for unsupported or already-adopted brownfield projects with a clear note to the user

For web-vite, the generated-system flow must verify that the scaffold runner materializes:
- a router-mounted `src/main.tsx`
- React Router configuration under `src/app/` or the registry-selected equivalent
- a runtime CSS entry that includes Motif's generated globals/token bridge
- a project-local `tokens.ts` file for component imports if the Vite contract declares it

Keep the change additive and phase-safe:
- do not remove the existing token-transformer or globals.css generation steps
- do not re-implement scaffold logic directly in the workflow
- do not force brownfield projects back through greenfield scaffolding

Create `.claude/get-motif/references/composer-vite.md` using `composer-nextjs.md` as the reference pattern, but rewrite it for Vite + React Router conventions.

The overlay must cover, at minimum:
- File Output Rules
  - route pages under the registry-selected Vite pages pattern such as `src/pages/{RouteName}Page.tsx`
  - router/bootstrap helpers in `src/app/`
  - shared components in `src/components/`
  - no Next.js `src/app/{route}/page.tsx` or App Router semantics
- Import Rules
  - React imports, `react-router-dom` (`Link`, `NavLink`, `Outlet`, `createBrowserRouter`, `RouterProvider` as needed), `lucide-react`, and standard `<img>`
  - no `next/image`, `next/link`, or `next/font`
- Styling Rules
  - Tailwind utility classes only for JSX styling
  - no inline style objects
  - no raw CSS custom-property references in JSX
  - use the same semantic utility naming established by Motif's web token bridge
- Route Composition Rules
  - component output must align with client-side routing and Vite SPA placement
  - page components should be ordinary React components, not server components
- Anti-Slop Additions
  - reject Next.js-specific imports and file placement
  - reject monolithic single-file route trees
  - reject direct `.planning/` imports

Make the overlay standalone enough that `compose-screen.md` can simply inject it from the registry entry without extra workflow changes.
