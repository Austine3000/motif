The brownfield gate must no longer depend only on `package.json` plus `src/|app/|lib/|pages/`. Replace it with framework-signature-aware entry logic that catches common Vite and Expo layouts, including root-level Expo apps.

Update the decision flow so init behaves as follows:
- clear supported framework from scan:
  - map Next.js -> `web-nextjs`
  - map Vite -> `web-vite`
  - map Expo -> `mobile-expo`
  - tell the user Motif detected the platform and will adopt the existing project
  - skip greenfield scaffolding later in the workflow
- ambiguous React or conflicting signatures:
  - present a confirmation prompt instead of guessing
  - if scan data is stale and ambiguity remains, instruct the user to re-scan before adopting
- explicit user override:
  - allow override, but warn before overriding a clear brownfield detection

Persist the adopted platform exactly as the greenfield path does so downstream workflows consume a single platform source of truth.

Do not move scaffold execution back into init. Init decides adopt vs scaffold; generate-system performs scaffold work.
