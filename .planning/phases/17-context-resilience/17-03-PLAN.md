  <name>Task 1: Upgrade motif-context-monitor.js with Motif state display</name>
  <files>.claude/get-motif/hooks/motif-context-monitor.js</files>
  <action>
Replace the existing motif-context-monitor.js with an upgraded version that shows both Motif workflow state AND context percentage.

**Input:** JSON from stdin (Claude Code statusLine format) with `context_window.used_percentage`.

**Output format when Motif project active:**
`Motif: {vertical} | {PHASE} {screens_composed}/{screen_count} | next: {hint} | ctx:{pct}%`

Example outputs:
- `Motif: fintech | COMPOSING 3/5 | next: transactions | ctx:23%`
- `Motif: saas | SYSTEM_GENERATED 0/4 | next: /motif:compose | ctx:45%`
- `Motif: health | INITIALIZED 0/0 | next: /motif:research | ctx:12%`

**Output format when NO Motif project (no STATE.md):**
`Motif context: {pct}%` (same as current behavior for non-Motif projects)
Plus the existing color-coded warnings for high context usage.

**Implementation:**
1. Read stdin JSON, extract `context_window.used_percentage`
2. Attempt to read `.planning/design/STATE.md` from disk (using `process.env.CLAUDE_PROJECT_DIR || process.cwd()`)
3. If STATE.md exists and has valid YAML frontmatter:
   - Parse frontmatter inline (simple regex + line parsing — do NOT require motif-state.js, keep the hook self-contained for performance)
   - Extract: phase, vertical, screens_composed, screen_count, screens (for next hint)
   - Build next-action hint:
     - INITIALIZED -> `next: /motif:research`
     - RESEARCHED -> `next: /motif:system`
     - SYSTEM_GENERATED -> `next: /motif:compose`
     - COMPOSING -> `next: {first screen with status "planned"}` or `next: /motif:review` if all composed
     - REVIEWING -> `next: /motif:fix`
     - ITERATING -> `next: /motif:compose` or `next: /motif:review`
   - Combine with context percentage
4. If STATE.md missing or unparseable, fall back to context-only display (existing behavior)

**Colors (ANSI):**
- Motif label: CYAN (\x1b[36m)
- Phase/vertical: default (no color)
- Separators: DIM (\x1b[2m)
- Context percentage: GREEN (<50%), YELLOW (50-89%), RED (>=90%)
- Context warnings at >=50%: append recommendation text (same as current)

**Performance:** The hook MUST be fast (<10ms). readFileSync on a small file is <1ms. No child_process spawning. No async operations. Self-contained YAML parsing (inline, not imported from motif-state.js).

Keep the `#!/usr/bin/env node` shebang and `'use strict'`.

```xml
**Step 0 — Load state:**
Run `node .claude/get-motif/scripts/motif-state.js read` and parse JSON output.
- If `{"error": "missing"}` or `{"error": "corrupt"}`: run `node .claude/get-motif/scripts/motif-state.js recover`. If recovery succeeds, notify user: "State recovered from artifacts -- phase: {phase}, {N}/{M} screens". If recovery fails, warn: "No Motif state found. Proceeding without state context."
- Otherwise: state is loaded.

**Step 1 — Validate phase:**
If Phase is not [{ALLOWED_PHASES}]:
  WARN: "Current phase is {phase}. This command typically runs during [{ALLOWED_PHASES}]. Proceeding anyway."
  (Do NOT block. Proceed with the command.)

**Step 2 — Check prerequisites:**
If [{REQUIRED_ARTIFACTS}] do not exist:
  WARN: "Missing {artifact}. Running this command without it may produce inconsistent results. Consider running {PREREQUISITE_COMMAND} first."
  (Do NOT block. Proceed with the command.)
</gate_check>
```
