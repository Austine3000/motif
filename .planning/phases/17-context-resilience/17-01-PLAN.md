  <action>
Create a Node.js CLI utility at `.claude/get-motif/scripts/motif-state.js` that is the single entry point for all Motif state operations. No external dependencies — use only `fs`, `path`, and `process` built-ins.

**CLI interface (called via `node .claude/get-motif/scripts/motif-state.js <command> [args]`):**

1. `read` — Read STATE.md, parse YAML frontmatter, output JSON to stdout. If STATE.md is missing or corrupt (no valid `---` delimiters), output `{"error": "missing"}` or `{"error": "corrupt"}` with exit code 0 (callers handle recovery).

2. `update <key> <value>` — Read STATE.md, update a single frontmatter field, write back atomically. For the `screens` field, value is JSON string (e.g., `'[{"name":"login","status":"composed"}]'`). For scalar fields (phase, vertical, stack, etc.), value is a plain string.

3. `write <json>` — Full state write. Accepts JSON string with all frontmatter fields. Writes YAML frontmatter + preserves markdown body. Uses atomic write-then-rename pattern (write to STATE.md.tmp, then fs.renameSync).

4. `status-line` — Read STATE.md, output a formatted status string for the statusLine hook. Format: `Motif: {vertical} | {PHASE} {screens_composed}/{screen_count}`. Add next action hint based on phase:
   - INITIALIZED: `| next: /motif:research`
   - RESEARCHED: `| next: /motif:system`
   - SYSTEM_GENERATED: `| next: /motif:compose`
   - COMPOSING: `| next: {first_planned_screen_name}` (from screens list, first with status "planned")
   - REVIEWING: `| next: /motif:fix`
   - ITERATING: `| next: /motif:compose` or `| next: /motif:review`
   If STATE.md missing, output empty string (statusLine hook handles this gracefully).

5. `recover` — Scan `.planning/design/` artifacts and rebuild state. See recovery logic below. Output recovered state as JSON. If recovery succeeds, also write the recovered STATE.md atomically.

**YAML frontmatter parser (internal function, no dependencies):**
- Split content on `---` delimiters (regex: `/^---\n([\s\S]*?)\n---/`)
- Parse flat key-value pairs: `key: value`
- Parse list keys (key with no value followed by `  - item` lines)
- Parse nested object lists (`  - name: login\n    status: composed`)
- Return null if content has no valid frontmatter

**YAML frontmatter serializer (internal function):**
- Convert JS object back to YAML frontmatter string
- Scalars: `key: value`
- Arrays of objects: indented `  - key: value\n    key: value`
- Arrays of strings: `  - value`
- Wrap in `---` delimiters
- Preserve markdown body (everything after second `---`)

**Atomic write (internal function):**
```
const tmp = statePath + '.tmp';
fs.writeFileSync(tmp, content, 'utf8');
fs.renameSync(tmp, statePath);
```

**Recovery logic (for `recover` command):**
- `designDir` = `.planning/design/` (relative to CLAUDE_PROJECT_DIR or cwd)
- Phase inference chain (most specific first):
  - `reviews/*-REVIEW.md` exists -> REVIEWING
  - `screens/*-SUMMARY.md` exists -> COMPOSING
  - `system/tokens.css` exists -> SYSTEM_GENERATED
  - `DESIGN-RESEARCH.md` exists -> RESEARCHED
  - `PROJECT.md` exists -> INITIALIZED
  - None -> return null (no Motif project)
- Vertical: read PROJECT.md, match `/## Vertical\n(\w+)/` or `/vertical:\s*(\w+)/i`
- Stack: read PROJECT.md, match `/## Technical Stack\n(.+)/` or `/stack:\s*(.+)/i`
- Screen list: read PROJECT.md `## Screens (v1)` section, parse numbered lines
- Screen status: cross-reference with `screens/*-SUMMARY.md` filenames (composed) and `reviews/*-REVIEW.md` filenames (reviewed)
- Use `fs.readdirSync` with try/catch for directory scanning (no glob dependency)
- Output recovery notification to stderr: `"[Motif] State recovered from artifacts -- phase: {PHASE}, {N}/{M} screens"`

**State file path:** `path.join(process.env.CLAUDE_PROJECT_DIR || process.cwd(), '.planning', 'design', 'STATE.md')`

**Error handling:** Never throw. Always return structured JSON or empty string. Log errors to stderr only.
